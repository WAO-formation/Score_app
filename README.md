# WAO Score App

WAO! is a sports-league platform with two clients sharing one Firebase
backend:

- **`wao_mobile/`** — Flutter app for fans, players, and coaches (iOS/Android/web).
- **`wao-web/`** — React admin console for admins, moderators, and officials
  (scheduling games, live scoring, roster/team management, reporting).

Both talk directly to the same Firestore project — there is no separate
backend API. `wao_mobile/firestore.rules` is the single source of truth for
what any role is allowed to read or write; wao-web has no server-side code
of its own beyond a couple of Cloud Functions (see below).

## Architecture at a glance

```
wao_mobile (Flutter)  ──┐
                         ├──►  Firestore (wao-mobile-app-7e3c9)  ◄── wao-web (React/Vite)
wao_mobile/functions ────┘        (matches, teams, players,
 (Cloud Functions,                 teamStatistics, users,
  notify-on-goal,                  championships, venues,
  match-finished stats)            reports, news)
```

- **Firestore project**: `wao-mobile-app-7e3c9`. Both apps' Firebase config
  points here — wao-web via `wao-web/.env.local` (`VITE_FIREBASE_*`), mobile
  via `wao_mobile/lib/firebase_options.dart` (generated by FlutterFire).
- **Firestore rules**: `wao_mobile/firestore.rules`, deployed with
  `firebase deploy --only firestore:rules` from `wao_mobile/`. Role helpers
  (`isAdmin`, `isOfficial`, `isCoachOfTeam`, ...) gate every collection —
  see the file itself for the authoritative, current logic.
- **Cloud Functions** (`wao_mobile/functions/`): `notifyOnGoal` (pushes an
  FCM notification to fans who favorited a scoring team) and
  `onMatchFinished` (increments each player's `gamesPlayed` and rolls a
  team's `teamStatistics` forward). These require the Firebase project to
  be on the **Blaze** (pay-as-you-go) plan — Spark can't run Cloud
  Functions at all, even at zero usage. Deploy with
  `firebase deploy --only functions` from `wao_mobile/` once Blaze is
  enabled at https://console.firebase.google.com/project/wao-mobile-app-7e3c9/usage/details.
- No mock/seed data runs automatically anymore — an earlier auto-seeder
  that ran on every mobile app launch has been removed. Anything you see in
  either app is real data that a real signed-in account created.

## Repo layout

```
wao_mobile/            Flutter app
  lib/
    Model/              Data models (WaoMatch, WaoTeam, WaoPlayer, UserProfile, ...)
    View/                Screens, grouped by feature
    ViewModel/           Provider-based view models wrapping the services below
    core/services/       Firestore read/write logic (match/team/player, auth, notifications, news)
  firestore.rules        Security rules for the whole project (shared with wao-web)
  functions/              Cloud Functions (notifyOnGoal, onMatchFinished)

wao-web/                React + Vite admin console
  src/
    pages/                Route-level pages (Games, Teams, Management, ...)
    services/             Firestore read/write logic, mirrors wao_mobile's field names
    context/              GamesContext (live matches + throttled writes), AuthContext
  scripts/                One-off Node scripts: seed demo accounts, link a player to a
                          team, inspect/clean up Firestore data (see below)
  TEST_ACCOUNTS.md         Full detail on every demo account (see summary below)
```

## Running it locally

**wao-web**
```
cd wao-web
npm install
npm run dev          # http://localhost:5173
npm test              # vitest unit tests
npm run test:rules    # Firestore rules test suite (spins up the emulator)
```

**wao_mobile**
```
cd wao_mobile
flutter pub get
flutter run            # pick a device/emulator, or -d chrome for web
flutter analyze        # static analysis
```

## Roles & permissions

| Role        | Where it can sign in | What it can do |
|-------------|----------------------|----------------|
| `fan`       | mobile only          | Follow teams, view games/news, favorite matches |
| `player`    | mobile only          | Fan permissions + view their assigned team's roster, fixtures, match history, personal stats |
| `coach`     | mobile only          | Player permissions + add/remove players on their one assigned team's roster |
| `official`  | wao-web only         | Score the Judges category on matches they're assigned to as a judge (`/officiating`) |
| `moderator` | wao-web only         | Run live scoring for matches they're assigned to (`/my-games`) |
| `admin`     | both                 | Everything — create games, manage teams/rosters/users/venues/tournaments, assign moderators & judges |

Role is stored on `users/{uid}.role` and is admin-assigned only — nobody can
elevate their own role (enforced in `firestore.rules`, not just the UI). A
`player`/`coach` account's team is `users/{uid}.teamId`, also admin-assigned
— distinct from a fan's self-service `favoriteTeamIds`.

## Utility scripts (`wao-web/scripts/`)

Beyond the seed scripts above:
- `linkPlayerToTeam.js` (`npm run link:player-team`) — ties the demo player
  account to a real roster (`ashesi_thunder` by default).
- `checkMatches.js` — read-only dump of every `matches`/`teams` doc exactly
  as stored; useful when mobile and web disagree about what data exists.
- `cleanupFakeMatches.js` — one-off script that removed leftover fake match
  docs written by the old mobile auto-seeder. Safe to leave; re-running it
  is a no-op now that those docs are gone.

## Known limitations

- Cloud Functions are written but not deployed until the Firebase project
  is upgraded to Blaze (see above).
- Individual player scoring (goals/points per player) isn't tracked
  anywhere in the data model — WAO's scoring is per-zone
  (Kingdom/Workout/Oval-Crown/Judges), per team, not attributed to one
  player. `gamesPlayed` is the only real per-player stat.
- `teams/{id}.category` still has some docs using an older `campus`/
  `general` taxonomy instead of `senior`/`junior`/`youth`; both apps
  degrade gracefully (unrecognized values fall back to `senior` on mobile)
  but this hasn't been normalized in the data yet.
